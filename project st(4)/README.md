# پاسخ تمرین‌های عملی آزمایشگاه

## تمرین اول و دوم: HTML، CSS و JavaScript
پوشه `01-html-css-js` شامل سه فایل است:
- `index.html`: نمایش نام دانشجو، رشته و دانشگاه و دکمه پیام
- `style.css`: رنگ پس‌زمینه، اندازه متن و چیدمان
- `script.js`: تابع `showMessage` برای نمایش پیام با کلیک

**اجرا:** فایل `index.html` را با مرورگر باز کنید. نام و دانشگاه نمونه هستند و می‌توانید آن‌ها را با اطلاعات خودتان جایگزین کنید.

## تمرین سوم: صفحه Ionic
فایل `02-ionic/students.html` یک صفحه رابط کاربری با عنوان «مدیریت دانشجویان»، ورودی نام، دکمه ثبت و فهرست دانشجویان است. با کلیک روی ثبت، نام وارد فهرست می‌شود.

**اجرا:** فایل را در مرورگر باز کنید. چون فایل‌های Ionic از CDN دریافت می‌شوند، برای بارگذاری ظاهر Ionic اتصال اینترنت لازم است. این تمرین روی ساختار رابط کاربری تمرکز دارد و هنوز ذخیره‌سازی دائمی یا اتصال به سرور ندارد.

## تمرین چهارم: معماری Cordova
نمودار `03-cordova-architecture/architecture.svg` ارتباط اجزای اصلی را نشان می‌دهد:
1. HTML ساختار محتوا را می‌سازد.
2. CSS ظاهر صفحه را تعیین می‌کند.
3. JavaScript منطق و رویدادها را مدیریت می‌کند.
4. WebView محتوای وب را داخل برنامه نمایش می‌دهد.
5. افزونه‌های Cordova امکان درخواست قابلیت‌های بومی دستگاه را فراهم می‌کنند.
6. سیستم‌عامل قابلیت‌هایی مانند موقعیت مکانی را در اختیار افزونه قرار می‌دهد.

نکته: در معماری واقعی، افزونه‌ها رابط ارتباطی میان کد وب و APIهای بومی سیستم‌عامل هستند؛ نمودار، نمای ساده‌شده آموزشی است.

## تمرین پنجم: انتخاب فناوری

Ionic همراه با Capacitor یا Cordova می‌تواند برای سامانه ثبت درخواست مشتریان گزینه مناسبی باشد، زیرا رابط کاربری آن با فناوری‌های وب مانند HTML، CSS و JavaScript ساخته می‌شود و می‌توان از یک بخش زیادی از کد در Android و iOS استفاده کرد.

**دلایل قابل بررسی:**
- ساخت سریع فرم ثبت درخواست و فهرست درخواست‌ها با کامپوننت‌های آماده Ionic
- ارتباط با API از طریق درخواست‌های HTTP و نمایش پاسخ سرور
- امکان استفاده از قابلیت‌های دستگاه مانند موقعیت مکانی از طریق افزونه‌ها یا پلاگین‌های مناسب
- کاهش نیاز به پیاده‌سازی جداگانه رابط کاربری برای هر سیستم‌عامل
- امکان توسعه و نگهداری رابط کاربری با مهارت‌های رایج توسعه وب

**عوامل مهم پیش از انتخاب نهایی:**
1. **نیازمندی‌های فنی:** آیا برنامه به قابلیت‌های خاص دستگاه یا پردازش‌های سنگین نیاز دارد؟
2. **کارایی:** سرعت اجرا، مصرف حافظه و عملکرد روی گوشی‌های ضعیف باید آزمایش شود.
3. **امنیت:** احراز هویت، مجوزهای دسترسی، اعتبارسنجی ورودی‌ها و انتقال امن داده‌ها اهمیت دارند.
4. **سازگاری افزونه‌ها:** باید بررسی شود افزونه موقعیت مکانی و سایر قابلیت‌های موردنیاز با نسخه‌های هدف Android و iOS سازگار باشند.
5. **وضعیت اتصال اینترنت:** اگر سامانه باید آفلاین هم کار کند، طراحی ذخیره‌سازی محلی و همگام‌سازی لازم است.
6. **نگهداری و پشتیبانی:** به‌روزرسانی فریم‌ورک، افزونه‌ها و سیستم‌عامل‌ها باید قابل مدیریت باشد.
7. **مهارت تیم و هزینه:** تجربه اعضای تیم، زمان توسعه و هزینه نگهداری بررسی شود.

**مقایسه کوتاه:** Capacitor گزینه جدیدتر و معمولاً انتخاب پیشنهادی برای پروژه‌های جدید Ionic است و ارتباط با قابلیت‌های بومی را از طریق پلاگین‌ها فراهم می‌کند. Cordova راهکار قدیمی‌تر و دارای اکوسیستم افزونه‌های گسترده است؛ اما باید سازگاری افزونه‌ها و نیازهای پروژه بررسی شود.

**نتیجه‌گیری:** اگر سامانه بیشتر شامل فرم، فهرست، ارتباط با API و استفاده معمول از موقعیت مکانی باشد، Ionic همراه با Capacitor می‌تواند گزینه مناسبی برای نمونه‌سازی و توسعه چندسکویی باشد. انتخاب نهایی باید پس از ساخت نمونه اولیه و آزمایش کارایی، امنیت و سازگاری انجام شود.
